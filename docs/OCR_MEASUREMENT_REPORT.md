## 1. เงื่อนไขการวัด (สิ่งที่ "ถูกต้องครบแล้ว")

| รายการ | สถานะ | หลักฐาน |
|---|---|---|
| det model (`det/inference.onnx`) | อัปเดต 12:31, 4.8 MB | `ls -la assets/models/det/` |
| rec model (`rec/inference.onnx`) | อัปเดต 13:32, 7.9 MB | `ls -la assets/models/rec/` |
| dictionary (`rec/keys.txt`) | 525 บรรทัด, LF-only, บรรทัดสุดท้าย = space (`use_space_char`) | `wc -l` = 525, `tail` = ` $` |
| loader Python (`simulate_ocr.py`) | `rstrip('\r\n')` — ตรงกับ Kotlin `trim('\r','\n')` ทุกจุด | parity เทสต์ผ่าน |
| ไฟล์ทดสอบ | สลิป 8 ใบใน `/root/uploaded_slips/` | KBank 3 ใบ + SCB 5 ใบ |

**Pipeline ที่วัด (เหมือนแอปทุกขั้นตอน):**
```
Image → det (scale ≤960, /32 rounding, ImageNet mean/std)
      → row-band detection (prob ≥ 0.3, MIN_BAND_H = 4)
      → rec (H=48, width /8 rounding, mean/std 0.5)
      → CTC greedy decode (blank = idx 0, dict[idx-1])
```

## 4. ปัญหาที่พบใน Paddle (เทียบกับ Tesseract)

| หมวด | PaddleOCR | Tesseract (tha+eng) |
|---|---|---|
| ข้อความไทย (ชื่อธนาคาร/ผู้รับ) | เพี้ยนหนัก เช่น `ธกสกรโทยร...` (กสิกรไทย), `ร้านกงเงิน` (ร้านถุงเงิน), `นายอนชา สมมติรรมห` | อ่านไทยได้แม่น เช่น `นาย ทดสอบ`, `ร้านถุงเงิน` |
| จำนวนเงิน | 5/8 ใบ; 3 ใบเพี้ยน/หาย (`299. 00`, `Sร3100`, `13 00`) | 8/8 ใบ |
| สระ/วรรณยุกต์ | หายเป็นแถว (`โอนเงนสาเร็จ`, `จายบีลสาเรืจ`) | ครบถ้วนกว่า |
| ตัวเลข/เลข ref | อ่านได้แต่มี noise ปน (`M01621521250301E084910L`) | อ่านได้ใกล้เคียงจริง (`20260808TEST0000000000001`) |
| โลโก้ธนาคาร | พอจับได้ (`K+`, `SCB.`, `CB.`) | พลาดได้ (SCB → `020 0 568:`) |

## 5. สรุป / ข้อเสนอแนะ

**ผลการวัดชี้ว่า PaddleOCR ตัวปัจจุบันยังไม่เพียงพอที่จะตัด Tesseract ทิ้ง** สำหรับ
สลิป KBank/SCB ชุดนี้:

1. **ความเสี่ยงหลักคือจำนวนเงิน** — Paddle พลาด/เพี้ยน 3/8 ใบ ถ้า parser จับผิด
   จะบันทึกเงินผิดทันที (อันตรายกว่าการจับไม่ได้)
2. **ข้อความไทยเพี้ยนหนัก** — ชื่อผู้รับ/ธนาคารใช้ประกอบการตัดสินใจได้ยาก
3. **Tesseract อ่านเงินครบ 8/8** และอ่านไทยแม่นกว่า แต่ช้ากว่า (~2.6x) และ
   แอปยังไม่มี engine ฝัง (ต้อง integrate tesstwo)

**ทางเลือก:**
- **A. Tesseract เป็นตัวหลัก** (แม่นสุด แต่ต้องเขียน engine ใหม่ + ช้ากว่า)
- **B. Paddle ก่อน → fallback Tesseract** เมื่อ confidence/parse ต่ำ (เร็วเมื่อ
   ผ่าน แต่ต้องมีกลไกตรวจจับ "อ่านไม่ดี")
- **C. Fine-tune rec model ไทย** (PaddleOCR) — แก้ที่ต้นเหตุ แต่ใช้เวลา/ข้อมูล

**ไฟล์ในชุดนี้:**
- `slip_ocr_test/ocr_outputs/paddle/*.txt` — raw text Paddle (รอบล่าสุด 18:41)
- `slip_ocr_test/ocr_outputs/tess/*.txt` — raw text Tesseract
- `slip_ocr_test/simulate_ocr.py` — ตัวจำลอง SlipOcrEngine (Python)
- `slip_ocr_test/batch_ocr.py` / `benchmark_ocr.py` — รัน + วัดความเร็ว
- `app/.../slip/parser/SlipParser.kt` — parser หลัก (ทน noise แล้ว)
